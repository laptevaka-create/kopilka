# Шаг 3 — делегированная часть: контрактные тесты фильтров, справочника и редактирования

Дата: 2026-11-21. Исполнитель: агент. Проверка и приёмка: владелец проекта.

## Задача, поставленная агенту

После основной части шага 3 (справочник категорий, фильтры журнала,
редактирование и удаление транзакций, 186 тестов) делегировано:
закрепить контрактными тестами края, не покрытые основной частью, —
период через границу года и из одного дня, очистку ошибки фильтра,
живучесть фильтра по категории, поведение при удалении/переименовании
выбранной категории, двойное сохранение в режиме редактирования,
дубликаты имён в другом регистре; сверить `readme.md` и дневник шага
с кодом. Дефекты `src/` не править, а описать в отчёте с предложением
минимального исправления. Правки существующих файлов, коммиты и пуши
запрещены.

## Что выполнил агент

- 18 новых тестов в трёх файлах `tests/Kopilka.App.Tests/`:
  - `JournalFilterContractTests.cs` (8): период через границу года с
    итогами обоих годов и пробелами вокруг дат; период из одного дня;
    успешный повторный ApplyPeriod очищает FilterError; фильтр по
    категории переживает навигацию «›»; удаление выбранной в фильтре
    категории сбрасывает фильтр на «Все категории»; переименование
    выбранной категории сохраняет выбор по Id и обновляет подпись;
    удаление последней строки отфильтрованного списка обнуляет итоги
    без появления FilterError; отмена диалога редактирования не меняет
    журнал;
  - `CategoriesViewModelContractTests.cs` (7): переименование в то же
    имя — не ошибка; дубликат в другом регистре отклонён и при
    добавлении, и при переименовании в чужое имя; смена регистра
    собственного имени разрешена; новые категории получают sort_order
    в конец своего типа; null-выбор отключает команды и очищает
    панель; сохранение поверх удалённой категории объясняется
    («Категория уже удалена.»);
  - `TransactionEditModeContractTests.cs` (3): BeginEdit → смена счёта
    → Save хранит ту же запись с тем же Id, сумма из BeginEdit
    проходит парсер при повторном Save; двойной Save не плодит
    записей; BeginEdit очищает ошибки предыдущей попытки.
- Сборка 0 ошибок / 0 предупреждений, в том числе после удаления
  `bin/`/`obj`; `dotnet test` — 204 теста (80 Core + 124 App).
- Сверка документов: статус README, дерево файлов, абзац шага 3 и все
  утверждения дневника сошлись с кодом построчно; неточность
  формулировки дневника про «подпись типа в панели» честно отмечена
  как нюанс, а не расхождение по поведению.
- Вскрытый дефект `src/`: `CategoriesViewModel.DeleteCategory` в ветках
  `Deleted`/`NotFound` не сбрасывает `SelectedCategory` — без отклика
  `ListBox` (юнит-тест, другая оболочка) панель показывает удалённую
  категорию, команды остаются включёнными. Агент корректно не правил
  код, описал сценарий с минимальным исправлением и намеренно не
  добавлял красный тест.
- Отдельно отмечена латентная хрупкость (не дефект): индексатор
  `categoriesById[...]` в `MainViewModel.Reload` при битой ссылке
  упал бы `KeyNotFoundException`; предложена подстановка заглушки.
- Честная оговорка в отчёте: один собственный тест агента при первом
  прогоне упал из-за нереалистичного сценария (удаление категории
  в обход `InUse`/`Restrict`); сценарий переписан на реальный до сдачи.

  `NotFound` после `Reload()` добавлено `SelectedCategory = null` —
  сеттер сам очищает `EditName`/`EditHasLimit` и отключает команды.
- Добавлен тест `Delete_UnusedCategory_ClearsSelectionAndPanel`
  (в файл владельца `CategoriesViewModelTests.cs`): после удаления

  исключения; поведение зафиксировано как решение в дневнике шага.
