# Шаг 6 — делегированная часть: контрактные тесты регулярных платежей

Дата: 2026-11-21. Исполнитель: агент. Проверка и приёмка: владелец проекта.

## Задача, поставленная агенту

После основной части шага 6 (движок начислений, репозиторий шаблонов,
атомарный начислитель, окно шаблонов, 342 теста) делегировано:
закрепить контрактными тестами края против норматива
`docs/specs/finance-rules.md` (раздел `RecurringEngine`) — переход
31-го через февраль, `lastApplied` внутри диапазона и на его границе,
однодневные диапазоны, цепочки вызовов без дублей, выключение и
повторное включение шаблона, неприкосновенность истории, атомарность
при сбое сохранения, нормализация ввода в окне шаблонов, отсутствие
лишних начислений у фильтров и сброса периода, порядок
«начисление → перезагрузка журнала»; сверить спеку, README и дневник
шага с кодом. Дефекты `src/` не править, а описывать в отчёте.
Правки существующих файлов, коммиты и пуши запрещены.

## Что выполнил агент

- 39 новых тестов в пяти файлах:
  - `RecurringEngineContractTests.cs` (Core, 10): 31-е через
    январь–февраль–март в обычный (28-е) и високосный (29-е) год
    с восстановлением 31-го; `lastApplied` внутри диапазона — даты
    до него включительно не генерируются; `lastApplied` на конце
    диапазона — пусто; однодневные диапазоны (совпадает с датой /
    раньше / равен `lastApplied`); день 1 и день 15 — две даты
    по возрастанию; 29-е и 30-е февраля прижимаются к последнему дню;
  - `RecurringAccruerContractTests.cs` (Core, 6, реальная база):
    цепочка «до конца ноября → до конца декабря» без дублей;
    null-комментарий переносится как null; два шаблона на одну дату —
    обе записи одним вызовом; выключение (начислений нет, отметка
    не двинулась) и повторное включение (старая отметка догоняет
    декабрь без дублей); удаление шаблона не трогает созданную им
    транзакцию; **атомарность**: сбой единственного `SaveChanges`
    (сломанный FK у второго шаблона) не оставляет ни транзакций,
    ни отметок, а повтор после починки создаёт ровно по одной записи;
  - `EfRecurringPaymentRepositoryContractTests.cs` (Core, 7):
    круговой обход полей, возрастающие id из `Add` (AUTOINCREMENT
    не сбрасывается — id только из возвращаемого значения), порядок
    списка по дню и id, `Update` меняет редактируемые поля, но
    сохраняет `LastApplied` (критично для реактивации), неудачные
    Update/Delete — false;
  - `RecurringViewModelContractTests.cs` (App, 10): комментарий из
    пробелов и табуляции → null при добавлении и правке; день с
    пробелами проходит Trim, «5.0» — нецелый; после добавления поля
    панели сохраняются (второй шаблон той же кнопкой); точная подпись
    « — выкл» только у выключенного; сброс выбора к значениям по
    умолчанию; две ошибки — двумя строками в порядке проверки;
    варианты списков: расходы вперёд, по умолчанию «Продукты»
    и «Наличные»;
  - `MainViewModelRecurringContractTests.cs` (App, 6): сброс периода
    и смена фильтра категории не начисляют; при произвольном периоде
    окно шаблонов начисляет до конца **сохранённого** месяца;
    прочие окна и отмены экспорта/импорта не начисляют;
    начисление выполняется до перезагрузки журнала — созданная запись
    видна сразу ( и при запуске, и после закрытия окна шаблонов).
- Сборка 0/0, включая чистую пересборку без `bin/`/`obj`; два
  промежуточных падения сборки были в собственных тестах (EF-анализатор
  запретил интерполированный `ExecuteSqlRaw`, в xunit нет
  `Assert.DoesNotEndWith`) — исправлено параметризованным `ExecuteSql`
  и `Assert.False(...EndsWith(...))`, без правок `src/`.
- Сверка документов: спека, README и дневник — построчно; найдены
  два расхождения спеки (формулировка «день создания»; отсутствие
  описания произвольного периода) и дубль раздела `RecurringEngine`
  в README (усечённый блок рядом с полным). Честно отделены
  наблюдения (недостижимые в модальном окне разыменования) от
  дефектов.
- Корректно атрибутировала правки владельца в своих файлах прошлых
  шагов (`M` у `*ContractTests` — это добавление параметра начислителя
  в конструкторы `MainViewModel` до начала её части).

## Независимая проверка

- Все пять файлов прочитаны целиком: тесты детерминированы, ожидания
  заданы явно, комментарии объясняют сценарии; тест атомарности

  ровно пять новых файлов.
