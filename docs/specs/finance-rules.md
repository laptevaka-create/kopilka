# Нормативные правила движков расчёта

Спецификация фиксирует правила детерминированных движков: входы,
выходы, формулы и границы. Код движков — `src/Kopilka.Core/Engines/`,
правила здесь — источник истины: тесты движков проверяют именно эти
утверждения. Все суммы — целые копейки (`long`); рубли появляются
только при выводе.

Разделы `BudgetEngine` и `CsvValidator` нормированы ниже;
`RecurringEngine` (шаг 6) дополнит спецификацию по мере реализации.

## BudgetEngine — статусы месячных бюджетов

Назначение: сказать пользователю, как категория расхода живёт
относительно лимита месяца (ФТ-4). Чистая функция: без базы,
без интерфейса, без состояния.

### Входы

| Вход | Тип | Ограничение |
| --- | --- | --- |
| `limitKopecks` | long | > 0 |
| `spentKopecks` | long | ≥ 0 |
| `currentDay` | int | 1..дней в месяце |
| `daysInMonth` | int | 28–31 |

Нарушение входов — исключение (`ArgumentOutOfRangeException`):
движок не угадывает, а отказывает громко.

### Выход

`BudgetSnapshot`:

| Поле | Тип | Смысл |
| --- | --- | --- |
| `Status` | `BudgetStatus` | `Ok` / `Attention` / `Exceeded` |
| `RemainingKopecks` | long | `лимит − потрачено`; отрицателен при превышении |
| `AvailablePerDayKopecks` | long? | только для `Ok`/`Attention`; у `Exceeded` — null |

### Статусы

| Статус | Условие |
| --- | --- |
| «в норме» (`Ok`) | потрачено < 80 % лимита |
| «внимание» (`Attention`) | 80 % лимита ≤ потрачено < лимит |
| «превышен» (`Exceeded`) | потрачено ≥ лимит |

Порог 80 % **включительный**: ровно 80 % — уже «внимание».
Сравнение без плавающей точки: `потрачено · 5 ≥ лимит · 4`
(промежуточно `decimal`, чтобы большие величины не переполняли `long`),
поэтому границы точны на любых суммах.

### «Доступно в день»

Для статусов «в норме» и «внимание»:

```text
available_per_day = (лимит − потрачено) / (дней в месяце − текущий день + 1)
```

- текущий день считается **оставшимся**: в последний день месяца
  «доступно в день» равно остатку целиком;
- деление целочисленное, вниз до копейки — остаток не «размазывается»
  по дням;
- у «превышен» поля нет (null): остаток отрицателен, дневной нормы
  не существует.

### Текущий день для показанного месяца

`currentDay` задаёт вызывающая сторона (главное окно):

| Показанный месяц | `currentDay` | Причина |
| --- | --- | --- |
| текущий | сегодня (по `IClock`) | честная норма на остаток месяца |
| прошлый | последний день месяца | месяц весь прошёл: «в день» = остатку |
| будущий | первый день | месяц весь впереди: норма на весь месяц |

### Панель бюджетов

- показывает только категории **расхода** с признаком лимита
  (`categories.has_limit`);
- категория с признаком лимита, но без бюджета на месяц, — строка
  «не задан» (серый статус, без «доступно в день»): отсутствие
  бюджета заметно, а не молчит;
- «потрачено» считается по **всем** транзакциям категории за месяц,
  без фильтра журнала: фильтр — про просмотр, бюджет — про контроль;
- при произвольном периоде (фильтр «с — по») панель скрыта: бюджет
  задан на месяц, к произвольному периоду он не привязан;
- пара (категория, месяц) уникальна (`ix_budgets_category_month`):
  повторное сохранение лимита обновляет запись, не создаёт новую.

## CsvValidator — обмен CSV

Назначение: экспорт транзакций месяца в файл и импорт обратно
(ФТ-5). Экспорт строит текст, импорт проверяет построчно — без
исключений наружу: результат всегда отчёт «импортировано X,
пропущено Y».

### Формат файла

- колонки: `дата;счёт;категория;сумма;комментарий` — пять, разделитель
  «;», без строки заголовка;
- кодировка UTF-8; экспорт пишет с BOM (Excel открывает кириллицу
  корректно), чтение метку снимает — файл читается и без неё;
- дата: `ДД.ММ.ГГГГ` на экспорте; импорт принимает также
  `ГГГГ-ММ-ДД`;
- сумма: рубли с запятой и копейками («1250,50»); при импорте
  допустимы пробелы-разделители тысяч и точка вместо запятой
  (точка — опечатка запятой, как в ручном вводе); сумм с более чем
  двумя знаками после запятой не существует — округление до копейки,
  половина от нуля вверх («0,005» ₽ → 1 копейка), округлившееся
  к нулю — отказ «неположительная сумма»;
- комментарий: пустое поле — пустой комментарий (null); поле,
  содержащее «;» или ASCII-кавычку, берётся в кавычки, внутренние
  кавычки удваиваются — файл читается обратно без потерь;
- комментарий обрезается по краям при импорте — как и ввод из
  интерфейса;
- перенос строки внутри поля не поддерживается (интерфейс его
  не вводит).

### Правила проверки строки

- пустые строки (и завершающие переводы) игнорируются, ошибками
  не считаются; номера строк — с единицы, включая пустые;
- счёт и категория разрешаются по имени: имя не найдено — отказ;
  имя категории, встречающееся и в доходах, и в расходах, — отказ
  «неоднозначная категория» (колонки типа в формате нет);
- строка с ошибкой пропускается целиком, обработка продолжается —
  битый файл не прерывает работу;
- кавычка внутри некавычного поля открывает секцию кавычек:
  не закрывшаяся до конца строки — отказ «незакрытая кавычка»;
  закрывшаяся парная — снимается, поле читается без кавычек
  (правило лояльного CSV). Экспорт поля с кавычкой всегда оборачивает
  кавычками целиком и удваивает внутренние, поэтому для файлов,
  созданных приложением, потерь нет;
- причины отказа (формулировки — часть контракта):
  «незакрытая кавычка», «неверное число колонок: N вместо 5»,
  «битая дата: «X»», «неизвестный счёт: «X»», «неизвестная
  категория: «X»», «неоднозначная категория: «X» — имя есть
  и в доходах, и в расходах», «битая сумма: «X»», «слишком большая
  сумма: «X»», «неположительная сумма: X»;
- валидная строка сохраняется как транзакция: сумма — в копейках,
  положительная; отказ базы при сохранении переводит строку
  в пропущенные с причиной «не сохранена: база отказала», импорт
  продолжается.

### Отчёт импорта

Формат — одна строка «Импортировано X, пропущено Y.»; при Y > 0
далее перечень по пропущенным: «строка N: причина». Экспорт и импорт
без диалогов работают с показанным месяцем: экспорт выгружает
транзакции месяца, кнопки экспорта и отчёта отключены при
произвольном периоде (бюджет, отчёт и экспорт — месячные операции);
импорт доступен всегда — записи приходят со своими датами.
