# Шаг 0 — каркас решения

## Задача шага

Создать скелет приложения: решение из двух проектов, DI-композицию,
источник времени за интерфейсом, пути к данным и пустое главное окно.
Критерий готовности: `Kopilka.Core` собирается без `-windows`,
сборка — 0 ошибок и 0 предупреждений.

## Что сделано

- Решение `Kopilka.sln` из двух проектов:
  - `src/Kopilka.Core` — `net10.0`, переносимая библиотека без WPF
    и Windows-стеков. Пока содержит `IClock`/`SystemClock` (источник
    времени) и `AppPaths` (пути к `%LOCALAPPDATA%\Kopilka`,
    обычный и демо-режим);
  - `src/Kopilka.App` — `net10.0-windows`, WPF, на выходе `Kopilka.exe`.
    Пустое главное окно и DI-контейнер в точке входа: `SystemClock`,
    `AppPaths` (выбор по ключу `--demo`), `MainWindow`.
- Тестовый проект `tests/Kopilka.Core.Tests` (xunit): пути, часы
  и архитектурный тест, который читает csproj ядра и проверяет,
  что там нет `net10.0-windows` и `UseWPF`.
- `TreatWarningsAsErrors` во всех трёх csproj: «0 предупреждений» —
  не обещание, а проверяемое свойство сборки.
- `.gitignore`: артефакты сборки, `.vs`, локальные базы.
- README: концепция, принципы, границы MVP, схема БД V001, таблица
  шагов, демо-сценарий, сборка.

## Как проверено

- `dotnet build Kopilka.sln` — успешно, 0 ошибок, 0 предупреждений.
- `dotnet test` — 10 тестов, все зелёные
  (5 по путям, 3 по часам, 2 архитектурных).
- Ручной запуск `dotnet run --project src/Kopilka.App` — открывается
  окно «Копилка — учёт личных финансов», каталог
  `%LOCALAPPDATA%\Kopilka` создаётся.

## Решения и компромиссы

- **Классический `.sln`, не `.slnx`.** SDK 10 по умолчанию создаёт
  `.slnx`; я пересоздала как `.sln`, чтобы решение открывалось любым
  Visual Studio и любым SDK — на чужой машине сюрпризы не нужны.
- **Core без единого NuGet-пакета.** DI и логирование живут в App
  (композиция), SQLite появится в Core на шаге 1 вместе с хранилищем.
  Так ядро остаётся переносимым, и архитектурный тест фиксирует это.
- **`AppPaths` с открытым конструктором.** Фабрики `ForDefault`/`ForDemo`
  задают стандартные пути, а конструктор позволяет тестам проверить
  создание каталога во временной папке, не трогая настоящий
  `%LOCALAPPDATA%`.
- **Демо-режим выбран на старте по `--demo`**, а не настройкой в базе:
  к моменту чтения настроек файла базы может ещё не быть, а демо
  обязано работать на чистой машине.
- **Шаги тестов и сборка идут в 0/0.** Первый запуск архитектурного
  теста упал из-за проверки `DoesNotContain("-windows")` — подстрока
  нашлась в комментарии csproj. Поправила проверку на целевой
  фреймворк (`net10.0-windows`): тестируется свойство проекта,
  а не текст комментариев.
