# Шаг 4 — бюджеты и контроль лимитов

Дата: 2026-11-21. Ветка: main (коммит отдельным, после приёмки).

## Что сделано

- **`BudgetEngine`** (`src/Kopilka.Core/Engines/`): чистая функция
  статусов — входы (лимит, потрачено, текущий день, дней в месяце),
  выход-снимок (статус, остаток, «доступно в день»).
  - Порог 80 % считаю без плавающей точки: `потрачено·5 ≥ лимит·4`
    через `decimal` — границы точны на любых величинах, включая
    близкие к `long.MaxValue` (проверено тестом).
  - «доступно в день» — только у «в норме» и «внимание», текущий день
    считается оставшимся, деление вниз до копейки.
  - Некорректные входы — исключения с причиной: движок не угадывает.
- **Хранилище бюджетов**: `IBudgetRepository` + `EfBudgetRepository`
  — `ListByMonth`, `GetByCategoryAndMonth`, `Set` (upsert: пара
  (категория, месяц) уникальна индексом, повторное сохранение
  обновляет), `Remove`. Схема не менялась — таблица `budgets` была
  создана ещё миграцией `InitialCreate`, проверка `Delete` справочников
  на использование бюджетами закрыта на шаге 2.5.
- **Суммы по категориям**: `ITransactionRepository.SumByCategory(from, to)`
  — один группирующий запрос вместо перебора транзакций на клиенте.
- **Панель бюджетов** в главном окне: категории расходов с признаком
  лимита, колонки «потрачено / лимит / остаток / в день / статус»,
  статус цветом (зелёный / янтарный / красный).
  - «Потрачено» — по всем транзакциям месяца, без фильтра журнала:
    фильтр — про просмотр, бюджет — про контроль.
  - Категория с лимитом, но без бюджета — строка «не задан»:
    отсутствие бюджета заметно, а не молчит.
  - При произвольном периоде панель скрыта: бюджет месячный.
  - Текущий день для формулы: текущий месяц — сегодня по `IClock`,
    прошлый — последний день (месяц прошёл), будущий — первый
    (месяц впереди). Правила нормированы в спеке.
- **Окно «Бюджеты»** (`BudgetsWindow` + `BudgetsViewModel`): лимиты
  показанного месяца; поле суммы, «Сохранить», «Убрать лимит»;
  валидация как в транзакциях (пусто / не число / не положительное).
- **Спецификация правил** `docs/specs/finance-rules.md`: входы/выходы,
  порог 80 % включительно, формула «доступно в день», целочисленное
  деление, правила текущего дня, поведение панели. Разделы
  `RecurringEngine` и `CsvValidator` заявлены на шаги 6 и 5.

## Решения и компромиссы

- **Порог через `decimal`, а не `double`.** 80 % — дробный порог,
  но копейки целые: умножение на 5 и 4 через `decimal` даёт точное
  сравнение без ошибок представления двоичных дробей.
- **«Доступно в день» только у живых статусов.** У «превышен»
  остаток отрицателен — дневной нормы не существует; пустое значение
  показывается прочерком, а не нулём.
- **Бюджет не наследуется между месяцами.** Лимит ноября не создаёт
  лимит декабря — задавать каждый месяц отдельно (сказано в окне
  бюджетов текстом). Иначе «тихий» бюджет расходился бы с фактом.
- **Прошлый месяц — остаток на один день.** Формула требует текущий
  день; для закрытого месяца честный ответ — «сколько осталось
  сверх лимита», поэтому день = последний. Правило зафиксировано
  в спеке, а не спрятано в коде.
- **Панель вместо модального окна.** Статусы видны постоянно рядом
  с журналом, редактирование лимитов — отдельным окном по кнопке.
