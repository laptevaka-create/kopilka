# Шаг 5 — отчёт месяца и обмен CSV

Дата: 2026-11-21. Ветка: main (коммит отдельным, после приёмки).

## Что сделано

- **Отчёт месяца** (ФТ-5.1): `ReportViewModel` + окно `ReportWindow` —
  секции «Доходы» и «Расходы», по каждой категории с движением сумма
  и доля в объёме своей части, итоги по частям и сальдо. Строки — по
  убыванию суммы, доля — один знак после запятой (`66,7 %`,
  у единственной категории `100,0 %`).
- **Экспорт CSV** (ФТ-5.2): транзакции показанного месяца в файл
  `дата;счёт;категория;сумма;комментарий` — разделитель «;», сумма
  в рублях с копейками, пустой комментарий — пустое поле. Кодировка
  UTF-8 с BOM: Excel открывает кириллицу корректно, чтение метку
  снимает. Поле с «;» или ASCII-кавычкой берётся в кавычки, внутренние
  кавычки удваиваются — файл читается обратно без потерь.
- **Импорт CSV** (ФТ-5.3): `CsvValidator` в Core — построчная
  проверка без исключений наружу. Причины отказов точные: неверное
  число колонок, битая дата, битая/неположительная/слишком большая
  сумма, неизвестные счёт или категория, неоднозначное имя категории
  (есть и в доходах, и в расходах — колонки типа в формате нет),
  незакрытая кавычка. Пустые строки игнорируются, номера строк
  сквозные, BOM и CRLF съедаются. Итог — окно отчёта
  «Импортировано X, пропущено Y» с перечнем причин; битая строка
  не прерывает разбор, ошибки чтения/записи файла показываются
  отдельным окном, приложение не падает.
- **Круглый обмен**: экспорт → удаление записей → импорт
  восстанавливает транзакции дотошно, включая комментарий с «;» —
  кавычки снимаются парсером.
- **Разбор сумм переехал в Core** (`MoneyParser`): правила одни
  для ручного ввода и CSV, `MoneyText.TryParseRubles` делегирует.
- **Русские даты — в одном месте** (`CalendarText`): заголовок
  месяца дублировался в главной модели и окне бюджетов, добавилось
  окно отчёта — теперь хелпер один.
- Отчёт, экспорт и импорт — кнопки в шапке; при произвольном
  периоде отчёт и экспорт отключены (месячные операции), импорт
  доступен всегда: записи приходят со своими датами.
- Спецификация `docs/specs/finance-rules.md` дополнена разделом
  `CsvValidator`: формат, кавычки, причины, отчёт, режимы кнопок.

## Решения и компромиссы

- **Неоднозначная категория — отказ, а не угадывание.** Имя
  уникально внутри типа, но «Прочие» может быть и доходом, и
  расходом; колонки типа в формате нет — строка пропускается
  с причиной, а не сохраняется в случайно выбранный тип.
- **BOM на экспорте.** Excel открывает UTF-8 CSV с меткой корректно;
  без метки кириллица в Excel превращается в мусор. Читатель метку
  снимает, файл без BOM тоже принимается.
- **Пустые строки — не ошибки.** Завершающий перевод файла не должен
  портить отчёт «пропущено Y»; пустота внутри файла тоже не несёт
  информации для пользователя.
- **Импорт добавляет, не синхронизирует.** Повторный импорт того же
  файла задвоит транзакции — CSV здесь перенос данных, а не
  синхронизация; это сказано в дневнике и видно по кнопке
  (синхронизация потребовала бы ключей строк — вне MVP).
- **Кавычки внутри некавычного поля — правило, а не дыра.**
  Одиночная (незакрытая) — громкий отказ; парная — снимается
  (лояльный CSV). Экспорт такие поля оборачивает кавычками целиком,
  поэтому круглый обмен без потерь; потеря возможна только при
  ручной правке файла — правило зафиксировано в спеке и тестом.
- **Округление половины копейки — от нуля вверх.** «0,005» ₽ →
  1 копейка, «0,004» → 0 → «неположительная сумма». Правило общее
  с ручным вводом (один `MoneyParser`) и дописано в спеку.
